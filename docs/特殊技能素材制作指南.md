# 特殊技能素材制作指南

本指南介绍怎样用自己的截图建立本地技能识别素材，以及后续怎样维护。图片不进入公开源码包；公开包提供目录规范、文字截图计划和工具。自己截图可以减少对外部图库的依赖，但并不等于获得游戏官方对自动化或图片再分发的许可。

当前规则支持按截图证据区分技能阶段，不会仅因图片名写着“第二枪”就判定第二次射击成功。文件校验、识别准确率和真实战斗复现是三项不同的验证。

本流程只建立特殊技能素材库，不替代默认 HUD 视觉配置或 GameKee 学生图库；倒计时、费用等基础识别仍需对应配置。

## 一 统一目录

所有正在使用的学生特殊技能包放在一个根目录下：

```text
.local/special-skills/
  packs/
    hina-dress/
      manifest.json
      capture-plan.json             # 自己制作时由 init 创建；迁移的旧包可没有
      capture-sources.json          # 使用 crop 时自动记录来源
      banners/
        ex-activation-001.png
        followup-shot-001.png
        followup-shot-002.png
        followup-shot-003.png
      portraits/
        base-card-001.png
        shooting-card-001.png
      tooltips/
      cards/
      copy_cards/
      sources/                      # 自己保留的完整截图，程序不直接用于匹配
    toki/
      manifest.json
      ...
  backups/                          # 迁移备份，不参与运行时加载
```

- 一名学生一个目录，例如 `hina-dress`、`aris-armed`、`mika-swimsuit`、`noa-pajama`、`shun-swimsuit`、`ibuki`、`iroha`、`toki`、`rio`、`kisaki-swimsuit`。
- 目录和素材键使用小写英文字母、数字、连字符；服装算不同学生目录。目录名必须与清单的 `student_slug`、`id` 一致。
- 工作图片统一为 `<分组>/<素材键>-<三位样本号>.png`。例如同一装甲卡不同亮度的样本可命名为 `portraits/armor-card-001.png`、`portraits/armor-card-002.png`。
- 不把姓名、文件夹顺序或样本号作为自动判断依据。中文显示名、阶段、图片角色由 JSON 中的标签和规则决定。
- 原始截图放在该学生 `sources` 内，建议用易懂名称；已有历史原图保留原名。原始录制仍在 `recordings`，不为了整理素材而改写它。
- 每名学生只保持一份正在使用的 `manifest.json`。其他版本放到 `backups`，不要在 `packs` 下面复制出两个有相同规则 ID 的活动包。

## 二 各组到底截什么

| 分组 | 要截的内容 | 运行时作用 |
| --- | --- | --- |
| `banners` | 释放技能后新出现的技能名称文字条 | 施放与阶段证据；同名技能不能只凭此区分阶段 |
| `portraits` | 技能卡内部稳定的角色／形态图块 | 卡牌身份及特殊卡面比对；尽量排除费用、边框和冷却遮罩 |
| `tooltips` | 提起技能时屏幕上方能区分两种技能的说明文字 | 选卡上下文；同名技能的阶段区分可能依赖它 |
| `cards` | 完整技能卡，含卡面、费用与标记 | 参考图，不直接作为成功施放依据 |
| `copy_cards` | 莉音作用后的复制卡完整外观 | 可选参考图；运行时复制标记按青蓝发光框几何检测，不要求本组图片 |
| `sources` | 完整游戏客户区截图 | 保留来源与重新裁剪；不直接加入模板匹配 |

灰卡和正常可操作卡不能混为一类。若截图来自灰卡，须在计划中注明其用途，不能将其命名为“可用卡”就当作可操作证据。当前日奈灰卡检测仍是专门逻辑，并非所有多形态角色的通用冷却判断。

## 三 截图条件

1. 在游戏规则允许且不影响排名的练习场景中采样，使用窗口化、16:9、繁体中文标准 HUD。
2. 首选游戏客户区的无损 PNG。不要截任务栏、标题栏、视频播放器边框、聊天窗口或字幕。带黑边的旧图要先明确有效客户区。
3. 尽量保留整个客户区原图。截图时让所需名称条、卡面和说明完整、清晰、未被鼠标、特效或其他窗口遮挡。
4. 每个不同技能状态分别保留：施放前卡面、选中后的说明、施放后的新名称条。连续技也要保留中间灰卡、恢复可用及最终换牌画面，以便人工核对。
5. 对同名技能、多次射击、变身、搭乘和复制，不只截角色立绘。多留一段连续录像记录状态如何变化，但不要根据动作次数给识别器填答案。
6. 若某个状态无法稳定获得，先记录“未采集／未验证”；不要用其他学生或其他形态的图片代替。

当前截图计划的参考画面是 **1740×979**。这是模板坐标系，不要求游戏窗口必须设置成这个分辨率。工具先将你明确指定的客户区归一到该尺寸，再按参考坐标裁剪。

## 四 用现成截图计划建立本地包

以下命令都在项目根目录执行，不会联网下载，也不会修改原始录制。

### 4.1 查看可用计划

文字计划位于 `examples/special_skill_templates/`。它们不包含图片、原始录像或逐次操作答案；包含目标文件名、中文标签、参考裁剪框、像素尺寸和既有阶段规则。

以时为例，初始化目录：

```powershell
.\.venv\Scripts\python.exe tools/manage_skill_library.py init toki
```

这会创建 `.local/special-skills/packs/toki/capture-plan.json` 和分组目录，**不会立即创建 manifest**。此时尚未成为可加载素材包。已有同名学生目录时工具拒绝覆盖，请先备份，或用下面的独立工作目录。

本机已有可用库时，建议先在独立工作目录制作：

```powershell
.\.venv\Scripts\python.exe tools/manage_skill_library.py --root .local/special-skills/work/packs init toki
```

下文为简化展示使用默认目录。如果使用工作目录，后续每条命令都要在子命令前加同一个 `--root .local/special-skills/work/packs`。

### 4.2 读懂计划中的一个素材

```json
{
  "group": "portraits",
  "tag": "普通女仆卡面",
  "asset_key": "base-card",
  "image": "portraits/base-card-001.png",
  "expected_size": [80, 61],
  "suggested_roi": [1457, 812, 1537, 873],
  "offline_identity": true
}
```

- `tag`：给人看的标签，也会参与规则引用，不能随意改而不改引用。
- `image`：最终裁剪图在学生目录下的相对路径。
- `expected_size`：裁剪图的宽、高；本例必须是 80×61 像素。
- `suggested_roi`：历史样本在参考坐标系中的 `[左, 上, 右, 下]`，不是对你当前截图的自动定位结果。角色换到其他卡槽时，需要相应调整。
- `offline_identity`：允许该图参与离线特殊卡面身份核对。复制到新学生时不能盲目照搬。

计划中的 `optional: true` 且 `reference_only: true` 表示可选参考图。它们不存在时可以跳过；普通卡面、名称条和必需说明缺失时不会默默放行。

### 4.3 放入完整截图并裁剪

将自己的完整客户区截图保存为：

```text
.local/special-skills/packs/toki/sources/base-card.png
```

如果图中普通形态时正好位于上述示例位置，可执行：

```powershell
.\.venv\Scripts\python.exe tools/manage_skill_library.py crop toki --asset portraits/base-card-001.png --source .local/special-skills/packs/toki/sources/base-card.png --roi 1457 812 1537 873
```

`--roi` 总是在归一到 1740×979 后计算；不是原图未缩放前的坐标。若原图只有游戏客户区，工具默认使用整张图。若含标题栏／黑边，额外提供原图像素坐标的 `--viewport 左 上 右 下`，先排除它们，再做归一。

若学生在其他卡槽，请查看自己的归一画面，调整左、上坐标，并保持该项要求的图块宽高。不要直接照抄不对应画面的裁剪框，也不要拉伸一张截错的图凑尺寸。

工具不改源图，已有目标图片时拒绝覆盖；同时写入 `capture-sources.json`，记录源图哈希、有效客户区、参考尺寸和裁剪框。也可以自己用图片工具精确裁剪并放到指定位置；这种情况下程序只能记录裁剪图本身，不能自动还原完整来源。

### 4.4 按计划补齐其他状态

逐项检查 `capture-plan.json`：

- `banners`：技能条实际出现后的画面。
- `portraits`：对应形态的卡面内部。
- `tooltips`：选中该形态技能时的说明。
- 可选完整卡和复制卡：用于人工查阅；不据此推断复制成功。

对于时，`System: Abi-Eshuh` 可能共用名称条，因此计划中有变身／装甲攻击两套说明上下文。仅有一张同名技能条不能证明当前是哪个阶段。类似 `unknown-001.png` 的文件名表示名称条本身不能独立确定阶段，不应直接改成“确定变身成功”。

### 4.5 登记并校验

完成所有必需图后执行：

```powershell
.\.venv\Scripts\python.exe tools/manage_skill_library.py compile toki
.\.venv\Scripts\python.exe tools/manage_skill_library.py validate
.\.venv\Scripts\python.exe tools/manage_skill_library.py list
```

`compile` 检查文件、解码、尺寸、路径及规则引用，计算 SHA-256，生成 `manifest.json`。已有 manifest 时拒绝覆盖，避免不完整更新替换可用版本。

`validate` 检查整个活动库，包括已经在清单里登记的参考图；`list` 显示学生、分组和规则数量。参考图可在编译时不登记，运行时也不依赖它们。只有存在有效 manifest 的学生目录才会加载，单独放图片不会自动登记。规则引用了不存在的名称条／说明、跨包重复规则 ID、图片被改动或尺寸不符，都会报错。

若在工作目录制作，校验成功且程序没有运行录制、分析、复现任务时，再整体替换对应学生目录；先将原学生目录备份到 `backups`。不要只替换图片、保留旧哈希。

## 五 用自己的录像验证

1. 录一小段包含基础技能、特殊阶段、取消或失败输入的测试。
2. 自动分析时选择正确六人和服装，查看结果使用的素材包信息与证据。
3. 逐项对照视频：卡面身份、技能阶段、费用、倒计时、是否换牌和是否正确排除未释放操作。
4. 对零费追加攻击、同名技能或复制卡，确认没有借用后一个技能的名称条来证明前一个成功。
5. 加入未用于截模板的新录制测试。只匹配制作模板的那一帧属于自匹配，不能说明新场次准确。

文件检查通过不代表战斗策略、命中、状态切换机制或复现精度已验证。截图不够时保持待确认，不要降低阈值、强改结果或将所有状态统一认定成功。

## 七 新角色与新阶段怎样维护

新增学生无需修改识别器代码：复制一个合适的文字计划，修改 `student_slug`、`id`、稳定的 `content_id`、别名、参考尺寸、素材项和规则。使用自定义计划初始化：

```powershell
.\.venv\Scripts\python.exe tools/manage_skill_library.py init my-student --plan path/to/my-plan.json
```

`my-student` 必须与计划中的 `student_slug` 一致。不要复用另一个学生的 content_id；服装不同也要核对 ID。选定六人后程序按 content_id（旧包兼容别名）加载，不靠文件夹中文字猜学生。

每条 `variants` 规则至少声明：

| 字段 | 如何决定 |
| --- | --- |
| `id` | 全库唯一的稳定规则 ID，如 `toki-abi-eshuh-enter`，不要随图片重命名而改变 |
| `phase` | 描述有证据的技能阶段，如 `mode_enter`；未知机制不要补成确定状态机 |
| `banner_tags` | 与 assets 中名称条的 tag 精确一致 |
| `cost_kind` | `zero`、`positive` 或 `any`，应来自可确认的机制与画面 |
| `requires_cost_drop` | 是否必须看到扣费；不要直接给所有特殊技能设 false |
| `requires_selected_actor` | 是否需要已选中角色身份的独立证据 |
| `card_rotation` | `required` 或 `optional`；会重抽／保留卡的技能需要真实取证 |
| `required_context_tag` | 同名技能需要的提牌说明，必须确实存在于 tooltips |

`cards`、`copy_cards` 默认仅参考；`portraits` 是否用于离线身份由 `offline_identity` 等明确字段控制。若将来新机制无法用现有规则表达，应保留未知，再扩展引擎；不要通过随意填写 phase 名字假定已经实现相应状态机。

同一学生补样本时增加新的样本号，保留既有规则 ID；改中文标签时同步修改所有引用。不同语言、参考分辨率与 HUD 不要混成一个活动包。

## 八 本次迁移和备份

现有 16 个包已整理为 15 名学生目录，保留 123 张图片及 27 条规则。迁移统一了路径、补充尺寸和元数据，未修改图像字节及判定条件，原库位于 `.local/special-skills/backups/`。

工具支持只预览，不写入：

```powershell
.\.venv\Scripts\python.exe tools/manage_skill_library.py migrate
```

确需执行旧库迁移时加 `--apply`。迁移会先校验、构建新目录，再备份和切换，切换失败会恢复原库。已是新格式时不重复改写。迁移名称映射在 `examples/special_skill_student_slugs.json`，仅用于旧数据整理，不是新增角色必须修改的运行时白名单。

运行时仍能读取旧 1.0 平面路径清单以兼容用户旧库，但新制作流程统一使用 `layout_version: "2.0"`。不要把新、旧同一批包同时放在活动根目录，否则会出现重复规则。
